# Taico Menu macOS App

`apps/taico-menu` is a native macOS menu bar app for monitoring and updating
Taico tasks. It is intentionally menu-bar-only: the app sets the accessory
activation policy at launch and the bundled `Info.plist` generated by
`script/build_and_run.sh` sets `LSUIElement`, so it does not show a Dock icon.

## Project shape

The app is a Swift Package Manager project so it can be opened directly in
Xcode by opening `apps/taico-menu/Package.swift`. Source is split by
responsibility:

- `App/` owns the SwiftUI app entry point, app delegate, and scene setup.
- `Views/` owns the menu bar menu and the sign-in window.
- `Models/` mirrors the backend DTOs used by the app.
- `Stores/` owns observable app state and coordinates refresh, mutations, and
  realtime updates.
- `Services/` owns REST auth/API calls, Keychain persistence, and the minimal
  Socket.IO client.
- `Support/` contains small formatting and URL helpers.

This keeps the menu surface small while leaving room for future full-client
windows, settings, richer task details, and more Taico primitives.

## Backend contracts

The app uses the existing Taico backend surfaces:

- `POST /api/v1/auth/login` with email and password.
- `POST /api/v1/auth/refresh` for silent refresh.
- `POST /api/v1/auth/logout` for sign-out.
- `GET /api/v1/tasks/tasks` for the task snapshot.
- `PATCH /api/v1/tasks/tasks/:id/status` for status moves.
- `PATCH /api/v1/tasks/tasks/:id/assign` for assignment changes.
- `GET /api/v1/actors` for human and agent assignees.
- `GET /api/v1/meta/tags` plus task tag add/remove endpoints for tag changes.
- Socket.IO namespace `/tasks`, with `tasks.subscribe`, for live task events.

Web auth currently returns tokens as HTTP-only cookies rather than JSON fields.
The native app captures the `access_token` and `refresh_token` cookies from
`Set-Cookie` and sends them explicitly on REST and Socket.IO requests. Session
persistence is handled by `SessionStore`: it writes an app-owned Application
Support session file for stable local development relaunches and mirrors the
session into Keychain when Keychain access is available without interactive
prompts. Keychain reads use a noninteractive `LAContext` so development build
signature churn does not block the menu bar app behind a password dialog. The
app refreshes before expiry and retries refresh on 401.

## Realtime approach

The backend uses Socket.IO, not a raw WebSocket protocol. To avoid adding an
external dependency, `SocketIOTasksClient` implements the small Engine.IO v4
and Socket.IO subset this app needs:

- establish the websocket transport,
- connect the `/tasks` namespace,
- respond to ping frames,
- send `tasks.subscribe`,
- decode task created, updated, assigned, status-changed, and deleted events.

If the realtime stream drops, the app keeps the REST snapshot path as the source
of truth and reconnects with backoff after token refresh or snapshot reload.

## UX choices

The menu bar label is a compact native text readout: a task glyph followed by
`in-progress / for-review` counts. This deliberately avoids stacked SwiftUI
badge overlays because the macOS status item clipped those layouts too
aggressively. The menu contains a `tasks` section with four status submenus:
not started, in progress, for review, and done. Each task is itself a submenu
with status movement, assignee selection, and tag toggles. Selected assignees
and tags use standard SF Symbol checkmarks.

Snapshot loading, refresh, mutation, and session persistence work are dispatched
off the main actor, then applied to SwiftUI in small batches. Status menus render
the first 40 tasks in each bucket and show a `Showing 40 of N` footer for larger
buckets, because native macOS menus are not virtualized and rendering hundreds
of nested task submenus can block the status item.

Credentials are collected in a small sign-in window opened from the menu. This
keeps the primary task workflow menu based without forcing text entry into a
menu, which macOS menus are not designed to handle.

The default server URL is `http://localhost:2003`, matching the backend port in
`stack1.env`. The field is editable and persisted in `UserDefaults`.
